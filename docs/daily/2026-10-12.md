**⚠️ 本档技术发现（已回写 `knowledge/technical-notes.md`，编号 §3.143a~h）**
1. **🔴 sed 派生脚本的「日期常量」二次踩坑（§3.106 条款 17 同型复发）** —— `REF_BY_TRACK_NEW`（A股/港股 类下一参考交易日）由 10/09 档派生后仍为 **2026-10-12**，而本档（10/12 盘后）正确值 = **2026-10-13**；**若沿用会让 10/12 盘后事件被「事件日本日收盘」回填 = 前瞻泄漏**。**规则**：派生后必须逐项核对「写盘路径 + 日期常量 + 前档基准值 + 档型语义」四类，**其中「日期常量」须区分「事件日」与「下一参考交易日」两个概念**（§3.143a）。
2. **🔴 `sentiment_*.json` 顶层 `window` 与脚本内字面量易漏改（§3.106 条款 17 / §3.112d 同型）** —— sed 替换因**行尾多一个空格**未命中 `sents['window'] = ...`，产物落库后顶层 `window` 仍为 10/9 口径；**且该脚本无判重守卫（二次执行会重复 append）→ 只能直接修产物**。**规则**：派生脚本的 `sed` 替换必须**逐条 grep 验证命中**（`grep -c`），未命中即视为未改；落库类脚本必须内建判重键（§3.143b）。
3. **🔴 同日前序档统计「分阶段口径」不可信，须按「库内现状」重算（§3.139k 同型复发）** —— 10/12 盘中档 `session_added = 25`（漏计盘前 26 条、真值 51）、`session_backfilled_total = 0`（覆盖了盘前档的 2 条）。**规则**：盘后档一律以「库内现状」重算前序两阶段（`len([e for e in ev if window startswith 盘前/盘中])`、`prev_preopen['session_backfilled_total']`），并写 `session_prior_stat_correction` 自证（§3.143c）。
4. **🟡 硬编码「1 日样本 n 增量」当日必然失效（§3.139f 扩展）** —— 派生脚本把 `onesample_n_delta_total = 59` 与逐赛道增量写死；本档真值 = **+86**（且逐赛道分布不同）。**规则**：该类字段一律**运行时计算**（取 `prev['onesample'][t]['n']` 差），并保留 `onesample_n_delta_detail` 便于交叉核对（§3.143d）。
5. **🟡 金额补齐器白名单须逐档重建（§3.112e 第 3 次复发）** —— 盘后档新增 45 行逐券金额与六赛道市值，白名单若沿用 10/9 版会**大面积漏补**；反之「金额的整数近似记法」（四舍五入到元）易与指数点位/计数类数字混淆。**规则**：`--dry` 期望「补 0 处」；白名单构建以「本档产物字段（`tracks[].mv`/`pnl`、`detail[].est_pnl`、`hk_split_pnl`、纪律台账、QDII 段）**为源、逐条判「金额 vs 计数/点位」**，**禁止纳入** n/条数/adj 计数/HTTP 码/指数点位（§3.143e）。
