**⚠️ 本档技术发现（已回写 `knowledge/technical-notes.md`）**

1. **🔴 派生脚本的「状态标签 + 定性方向词」继承错误（§3.145a 第 2 次复发，本档派生初稿命中）** —— `calc_portfolio_close_20261014.py` 与 `calc_strategy_close_20261014.py` 由 10/13 版 `sed` 派生后，`hstech_4250.state` 仍为 10/13 的 **`close_level_break_widened` / `BROKEN_CLOSE_LEVEL_WIDENED`**、且 `HSTECH_prev` 被带入 **10/12 值 4169.57**（应为 10/13 值 4136.63）→ 若沿用会得出「走阔」的反向结论。**规则**：① `state` 类字段**禁止继承**，须由「本档 dist_pct vs 上一档 dist_pct」现算；② `judgement` 中的「收窄/走阔」须由公式生成而非誊抄；③ 派生脚本的**前档基准常量**（`*_prev`）与**状态字段**属同批必检项；④ 产物须写 `state_correction` / `state_derivation` 自证。
2. **🔴 `REF_BY_TRACK_NEW` 的「下一交易日」在派生中原地复制的陷阱（§3.106 条款 17 第 4 次复发）** —— `events_close_20261014.py` 由 10/13 版派生时，`REF_BY_TRACK_NEW` 全赛道被带成 **2026-10-14**（10/13 档的「下一交易日」），而本档（10/14 盘后）应为 **A股/港股/宏观/其他·宽基 = 2026-10-15**、**美股标普医药 = 2026-10-14**。**后果（已实测并修复）**：若沿用 10/14，10/14 盘后事件会被以「事件日本日收盘」回填 → **前瞻泄漏**。**规则**：派生后必须**逐赛道重算**该映射；**修复时不能只改脚本，必须回滚已写入的事件条目**（本档处置 = 从 `events-2026-10-14.json` 删除 23 条盘后条目 + 首次运行备份 `.bak_pre_close` + 修脚本后重跑，`ref_trade_day` 由 23 条全 10-14 → **20 条 10-15 + 3 条 10-14**）。
3. **🔴 并行编辑同一脚本会静默丢改动（工具使用层教训，本档首次实测）** —— 在同一轮对同一文件发起多个替换时，部分替换虽返回成功但**未落盘**（本档实测 8 处替换中 5 处丢失，仅 3 处生效）→ **规则：对同一脚本的多处修改必须串行、每改一处即回读校验（`grep`/`sed -n`），禁止依赖「成功」回执**。该规则同样解释了 §3.121c 反复出现「派生脚本残留字面量」的底层成因。
4. **🟡 `%` 格式化与文本内裸 `%` 冲突（报告脚本层）** —— 在 `%`-格式化的长字符串中写入「通信 −3.93% 居首」这类**未转义的裸百分号**会触发 `TypeError: not enough arguments for format string`（而非更直观的「unsupported format character」）。**规则：含大量中文百分比叙述的段落改用 f-string，或全部裸 `%` 写成 `%%`**；本档已改为 f-string。
